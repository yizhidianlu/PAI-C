## Pipeline state files

V1.0 introduces two new files under `<project>/.paic/state/`:

| File | Purpose | Schema |
|---|---|---|
| `pipeline.yaml` | 11-stage orchestrator state (current_stage, mode, consecutive_continues, stage_history) | `PipelineState` |
| `passport.yaml` | Append-only stage-boundary ledger (kind: boundary / resume + 12-char SHA-256 hash) | multi-doc YAML stream of `PassportEntry` |
| `passport.lock` | Cross-platform advisory file lock (auto-managed, never edit) | (binary) |
| `integrity_cache.json` | S2 batch verify cache keyed on (cite_key, sha256(normalized_title)) | JSON dict |
| `integrity_report.yaml` | Latest integrity gate run output | `IntegrityResult` |

All paths are added to `ProjectPaths` and tools auto-create on first
write.

## V1.1 — P3-1 + P3-2 shipped (incremental)

V1.1 closes out the two P3 items deferred from V1.0:

### P3-1 · Originality / plagiarism scan

Extends `paic_integrity_check` with a new `mode="originality"` standalone
path AND an `originality_enabled=True` opt-in auxiliary check during
existing `pre_review` / `final_check` runs.

- **Algorithm**: k-shingle Jaccard (default k=8 word shingles) against
  `library/summaries/<cite_key>.md` + `library/chunks/<cite_key>.json`.
  Pure Python, no external dependency.
- **Verdicts** (3 new `IntegrityIssue` kinds, disjoint from
  HALLUCINATION_KINDS / AI_FAILURE_MODE_KINDS):
  - `ORIGINALITY_VERBATIM` (jaccard ≥ 0.85) → severity=blocker
  - `ORIGINALITY_CLOSE_MATCH` (0.65–0.85) → severity=major
  - `ORIGINALITY_PARAPHRASE` (0.40–0.65) → severity=minor
- **Sample rates**: 30% (pre_review) / 50% (final_check) / 100%
  (standalone `originality` mode). Deterministic sampling (every Nth
  paragraph) so re-runs after fixes don't shuffle the unchecked set.
- **Heuristic only** — not a substitute for Turnitin / iThenticate.
  Report includes a Tool Limitation Disclaimer line.
- New file: `src/paic/integrity/originality.py` (~250 LoC)
- New tests: `tests/test_integrity_originality.py` (15 tests)

### P3-2 · /paic-process-summary

New SKILL + MCP tool (`paic_process_summary_generate`) that renders the
paper creation process record as markdown by reading 4 state files:

- `pipeline.yaml` — 11-stage history
- `passport.yaml` — Material Passport boundaries / resumes
- `runs.yaml` — LangGraph runs
- `state/integrity_report.yaml` — latest integrity gate output

Missing sources produce placeholder lines rather than hard errors —
even projects that never used `/paic-pipeline` yield a useful
runs+integrity summary. Pure render (no LLM call). LaTeX→PDF deferred
to V1.2 — markdown only in V1.1.

- New files: `src/paic/mcp_server/tools/process_summary.py`,
  `skills/paic-process-summary/SKILL.md`
- New tests: `tests/test_process_summary.py` (8 tests)

V1.1 final test count: **851 passed, 2 skipped** (842 → 851 in V1.0; +23
new originality + process-summary tests, 5 deltas from regressions
fixed during P3-1 wiring).

## Migration

V1.0 is fully backward compatible with v0.1:
- Old `.paic/` yaml schemas unchanged
- All v0.1 SKILLs / MCP tools still work
- `/paic-draft compose` (v0.3) is the fallback when you don't want the
  4-call cost; `/paic-draft compose-v2` (v0.4) is the new strict path
- Material Passport is opt-in (default off) — projects that don't
  enable it never see passport.yaml created

To enable the V1.0 features:

```yaml
# ~/.paic/config.yaml
passport:
  enable_reset_boundary: true   # if you want cross-session resume
```

That's it — the new SKILLs are auto-discovered by Claude Code from
`skills/` and the new MCP tools are auto-registered when you restart
the MCP server (after `pip install -e .` or equivalent).
